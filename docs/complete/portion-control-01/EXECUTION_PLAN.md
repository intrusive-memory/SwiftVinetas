## Terminology

> **Mission** — A definable, testable scope of work. Defines scope, acceptance criteria, and dependency structure.

> **Sortie** — An atomic, testable unit of work executed by a single autonomous AI agent in one dispatch. One aircraft, one mission, one return.

> **Work Unit** — A grouping of sorties (package, component, phase).

## Mission Scope

Stop iOS jetsam OOM kills during PixArt generation by giving MLX a real,
per-process memory ceiling so it self-throttles instead of spiking past the
jetsam cap. All changes are `#if os(iOS)`-fenced; macOS memory behavior is
intentionally untouched.

**In scope (this repo, SwiftVinetas, branch `development`):**
- New budget-configuration API on `VinetasMemory`.
- Wiring the API into the `PixArtEngine` load/unload/generate paths.
- Mirroring the configure call into `Flux2Engine` for symmetry (no-op on macOS).
- CI-safe unit tests for the new API.

**Out of scope (tracked as Open Questions, not sorties):**
- The one-line `AppLifecycleManager` change in the separate `~/Projects/Vinetas`
  app repo (different repo, different ship cycle) — see OQ-1.
- The distribution-build entitlement prerequisite check (requires downloading a
  signed `.ipa` from App Store Connect; not an autonomous code task) — see OQ-2.
- Version bumps / tagging — explicitly forbidden by the requirements doc; follow
  the normal `ship-swift-library` flow later.

### Sortie 1: Add iOS MLX budget API to `VinetasMemory` + CI-safe unit tests

**Priority**: 9 — highest. Depth 1 (blocks Sortie 2) ×3, foundation 1 (API reused by both engines) ×2, risk 3 (new tech: MLX process-global statics + `os_proc_available_memory`) ×1, complexity ~2 ×0.5. Execute first.

**Entry criteria**:
- [ ] First sortie — no prerequisites.

**Tasks**:
1. In `Sources/SwiftVinetas/Core/VinetasMemory.swift`, add the imports the new
   code needs: `import MLX` (unconditional) and an `#if os(iOS) import os #endif`
   block (for `os_proc_available_memory`). The file currently imports only
   `Foundation`.
2. Add `public static var processAvailableMemoryBytes: UInt64?` — on iOS returns
   `os_proc_available_memory()` as `UInt64` when `> 0`, else `nil`; on macOS
   returns `nil` (no per-process jetsam cap).
3. Add `public static func configureMLXBudgetForCurrentProcess(availableBytes:UInt64? = processAvailableMemoryBytes, safetyFraction:Double = 0.8, cacheLimitBytes:Int = 32 * 1_048_576)`.
   Body is `#if os(iOS)`-fenced: guard on `availableBytes > 0`, then set
   `MLX.Memory.memoryLimit = Int(Double(available) * safetyFraction)` and
   `MLX.Memory.cacheLimit = cacheLimitBytes`. No-op on macOS.
4. Add `public static func releaseMLXCache()` calling `MLX.Memory.clearCache()`.
5. Add unit tests to `Tests/SwiftVinetasTests/VinetasMemoryTests.swift` that
   inject a known `availableBytes` and assert `MLX.Memory.memoryLimit` and
   `MLX.Memory.cacheLimit` equal the expected derived values
   (`Int(Double(availableBytes) * safetyFraction)` and `cacheLimitBytes`).
   **Guard the test body with `#if os(iOS)`** so it is meaningful only where the
   clamp is active and no-ops on the macOS host run. Snapshot the two
   process-global statics before the assertion and restore them in teardown
   (they are process-wide and shared with `Understanding/*` MLX work). These
   tests run under `make test-unit-ios` (iOS Simulator), where `#if os(iOS)` is
   active and setting `memoryLimit`/`cacheLimit` is a plain static assignment
   requiring no device or GPU. (Resolution of OQ-3 — accepted recommendation.)

**Exit criteria**:
- [ ] `make build` succeeds (compiles on both platforms).
- [ ] `grep -n "processAvailableMemoryBytes\|configureMLXBudgetForCurrentProcess\|releaseMLXCache" Sources/SwiftVinetas/Core/VinetasMemory.swift` returns all three symbols.
- [ ] `make test-unit-ios` passes, including the new `#if os(iOS)`-guarded test(s) asserting the clamp values.
- [ ] `make test-unit` (macOS host) still passes (the new test no-ops there; confirms no regression and that the macOS build path is clean).
